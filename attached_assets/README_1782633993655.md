# Handoff: Abrechnung (Billing) Rework — Care Connect / Senioren Engel

## Overview
A redesign of the **Abrechnung** (billing / month-close) surface for the Care Connect
elderly-care operations app. It gives the operator (Geschäftsleitung) three things on one page:

1. **Wirtschaftlicher Überblick** — collapsible profitability cockpit (revenue, labour cost,
   contribution margin) broken down **by service** and drilled down **by employee**.
2. **Status der Termine & Rechnungen** — a shared pipeline showing where every appointment and
   invoice sits across the full lifecycle.
3. **A tabbed working area** with two equal surfaces:
   - **Termine — End-to-End**: appointments grouped per employee → per status, each row a
     deep-link to the individual appointment.
   - **Rechnungen verwalten**: "Noch zu erstellen" worklist + invoices grouped by status with
     row actions, multi-select and bulk operations.

All views are scoped by a **filter bar pinned to the top** of the page.

## About the Design Files
The file in this bundle (`Abrechnung.dc.html`) is a **design reference created in HTML** — a
working prototype showing the intended look, layout and interactions. **It is not production
code to copy.** The task is to **recreate this design inside the existing Care Connect codebase**
using its established stack and patterns:

- **React + TypeScript**, **Tailwind v4** (CSS-first `@theme`), **shadcn/ui** (new-york style),
  **lucide-react** icons, **wouter** routing, **TanStack Query** for data.
- Design tokens live in `client/src/design-system/` (`tokens.ts`, `index.css`).
- **All UI text is German — keep it.**

Use the existing primitives (`<Card>`, `<Button>`, `<Select>`, `<AlertDialog>`, `<Checkbox>`,
`StatusBadge`, `iconSize`, `componentStyles`, `colors`) rather than hand-rolling. The HTML uses
inline hex values and inline SVG icons **only because a prototype can't import your system** —
every one maps to a token or a lucide icon below.

## Fidelity
**High-fidelity.** Colors, typography, spacing, copy and interactions are final and intentional.
Recreate the UI faithfully, but **resolve every literal to the corresponding design-system token**
(see *Design Tokens → Mapping*). Do not introduce hues outside the §1.2 status palette.

## Screens / Sections

### 1. Filter bar  (top — scopes ALL views)
- **Purpose**: choose the period/scope every section below reacts to.
- **Layout**: one white card, `flex` row, `align-items:flex-end`, `gap:16px`, wraps.
- **Components** (each a labelled shadcn `<Select>`; label 12px muted `#8a8170`, control
  `h-~40px`, `rounded-[10px]`, border `#e3e6ea`):
  - Leading "FILTER" eyebrow with lucide `Filter` icon.
  - **Monat** (Januar…Dezember), **Jahr** (2026/2025), **Mitarbeiter:in** (Alle + names),
    **Kasse** (Alle Krankenkassen + payer list; this control grows `flex:1`).
- Note: an earlier "Leistung" filter and a "Stornos ausblenden" toggle were **intentionally
  removed** — do not re-add. Stornos are represented as their own status group in the bills tab.

### 2. Wirtschaftlicher Überblick  (collapsible)
- **Purpose**: profitability transparency for the selected scope.
- **Header** (click toggles collapse): lucide `TrendingUp` in a `#e8f3f1` rounded tile, title
  "Wirtschaftlicher Überblick" 19px/700, subtitle "Umsatz, Lohnkosten & Marge — {Monat Jahr}".
  When **collapsed**, show an inline summary string ("Umsatz … · Marge … (…%)") + a chevron that
  rotates 180°.
- **KPI row** — 4 tiles, `grid-template-columns:repeat(4,1fr)`, `gap:14px`,
  tiles `rounded-[15px]`, padding `17px 19px`:
  - **Umsatz** — bg `#f7f8fa`, value 29px/700 `#26303f`, sub "brutto, alle Leistungen".
  - **Lohnkosten** — value `#5a6573`, sub "an Mitarbeiter:innen".
  - **Deckungsbeitrag** — accent tile bg `#effaf6` border `#cdeee4`, value teal `#0f766e`,
    sub "Umsatz − Lohnkosten".
  - **Marge** — value colored by health (see margin-health rule), plus a thin progress bar
    (`height:6px`, track `#e9ecf0`, fill = margin %).
- **Toggle**: a segmented control (pill, `#f1f2f5` track) — **Nach Leistung** | **Nach Mitarbeiter**.
  Active segment = white pill, teal text `#0f766e`, border `#cdeee7`, subtle shadow.
- **Nach Leistung table** — 6-column grid
  `minmax(170px,1.7fr) 120px minmax(120px,1fr) minmax(120px,1fr) minmax(120px,1fr) 92px`, `gap:20px`.
  Header row (11.5px uppercase muted): Leistung · Menge · Umsatz · Lohnkosten · Marge · % (all
  numeric cols right-aligned). One row per service. Row 1 cell: service name 15px/600 + a rate
  sub-line e.g. "38 € / 16 € pro Std". `%` colored by margin health. **No distribution bars** —
  the % column is the only visual (bars were intentionally removed).
- **Nach Mitarbeiter table** — same column geometry; first cell = expand chevron + circular
  avatar (initials, `#e8f3f1`/`#0f766e`) + name. "Menge" cell stacks "{Std} Std" over "{km} km".
  **Umsatz** and **Marge** headers are click-to-sort (toggle asc/desc, show ↓/↑). Clicking a row
  expands an inset panel (`#f8f9fb`, `rounded-[13px]`) with a per-service breakdown (Hauswirtschaft
  / Alltagsbegleitung / Kilometer → Menge, Umsatz, Lohnkosten, Marge, %).

### 3. Status der Termine & Rechnungen  (pipeline — shared overview)
- **Purpose**: at-a-glance "where is everything", and a jump-off into the right tab.
- Header: lucide `ArrowLeftRight` / shuffle-style icon in `#eef2ff` tile; title 19px/700;
  subtitle "Status anklicken, um direkt zur passenden Liste zu springen".
- **Two phase groups** side by side, connected by a lucide `ArrowRight`:
  - **Termine**: Offen → Dokumentiert → Leistungsnachweis (unterschrieben).
  - **Rechnungen**: Rechnung erstellt → Versendet → Avis erhalten → Bezahlt.
- Each stage = a tinted card (`rounded-[14px]`, status bg/border), `label` 12.5px/600 in status
  color, a sub caption, big count 25px/700 `#26303f`, and the € sum in status color. Hover lifts
  `translateY(-2px)`.
- **Click behavior (cross-link)**: a *Termine* stage → switch to the **Termine** tab + set its
  status chip filter. A *Rechnungen* stage → switch to the **Rechnungen** tab + open the matching
  status group (`avis` maps to the "Versendet/Avis ausstehend" group).
- Below: two muted chips for side states — **Storniert** (count/€) and **Kunde nicht angetroffen**.
- **Tweak**: a `pipelineStyle` of `funnel` renders the same data as horizontal proportional bars
  (label · bar(width=count/max) · count · €) instead of the card flow. Implement as a view toggle
  if useful; default is `flow`.

### 4. Tabs  (working area)
Two pill tabs with count badges: **Termine — End-to-End** ({total appts}) and
**Rechnungen verwalten** ({offen} offen). Active tab = filled teal `#0d9488` pill, white text,
badge bg `rgba(255,255,255,.25)`. Inactive = `#f1f2f5` pill, `#5a6573` text, white badge.

#### 4a. Tab — Termine (End-to-End)
- Sub-header "Termine nach Mitarbeiter & Status" + count line. A "Status-Filter zurücksetzen ✕"
  button appears only when a status filter is active.
- **Status filter chips**: Alle + Offen + Dokumentiert + Leistungsnachweis + Rechnung erstellt +
  Versendet + Bezahlt, each with a count. Active chip is tinted to its status color; inactive is
  white/`#e3e6ea`. Chips and pipeline stages share one `statusFilter` state.
- **Per-employee expandable rows** (this mirrors the existing "Blocker" readiness-row pattern):
  - Collapsed header: avatar + name + small status-count pills ("{n} offen" rose,
    "{n} ohne Nachweis" amber, "{n} abgerechnet" violet) + "{total} Termine" + chevron.
  - Expanded: appointments grouped by status. Each group = a colored dot + "{n} {groupLabel}"
    (e.g. "2 offene(r) Termin(e)", "10 Termin(e) ohne Unterschrift"). Group label may wrap — keep
    `line-height:1.35` and a ≥10px gap to the first row.
  - **Appointment row** (the deep-link): tinted by status (`soft` bg, status border),
    `rounded-[10px]`; left = "{DD.MM.YYYY} {HH:MM}" (tabular-nums, status color) + client name +
    a service chip (Hausw./Alltagsb.); right = a status pill + an **"Öffnen ›"** affordance.
    **Each row must navigate to that appointment's detail** (this is the core "quick navigation"
    requirement — wire it to the appointment route).
- When a status filter is active, only employees having that status are shown, auto-expanded to
  just that group.

#### 4b. Tab — Rechnungen verwalten
- **Bulk action bar**:
  - "Alle auswählen" global checkbox (selects all selectable bills).
  - When ≥1 selected: "{n} ausgewählt", a **Status ändern …** dropdown (An Kasse senden / Als
    versendet markieren / Als bezahlt markieren / Stornieren — performs the **mass status change**),
    a **Sammeldruck …** dropdown with **two** options (**Nur Rechnungen** / **Rechnungen +
    Leistungsnachweise**), and "Aufheben".
  - Right: primary **+ Neue Rechnung**.
- **"Noch zu erstellen" group** (collapsible, teal-tinted header, count badge, caption
  "Leistungsnachweis unterschrieben — Rechnung fehlt"): one row per client = name + Kasse chip
  (+ optional amber warning line e.g. "Nur 1/2 dokumentierte Termine im Leistungsnachweis") +
  an outline **Erstellen** button (lucide `FileText`).
- **Bill status groups** (each collapsible): **Noch zu versenden** (Entwürfe, amber),
  **Avis ausstehend** (Versendet, violet), **Bezahlt** (green), **Storniert** (gray). Group header:
  **its own select-all checkbox** (per-status selection — selects every bill in that group;
  must `stopPropagation` so it doesn't toggle collapse), chevron, label, count badge, caption,
  and the group € sum (right).
- **Bill row**: row checkbox · invoice no. (`RE-2026-####`) · "Rechnung" badge (teal outline) ·
  status badge · "{client} → {Kasse}" (truncates with ellipsis, `flex:1 min-width:150px`) ·
  amount (700) + optional "inkl. MwSt." · status-specific action text (Entwurf → "An Kasse
  senden →" blue if a Kasse exists else "Als versendet markieren" teal; Versendet → muted
  "Versendet {date}") · "Stornieren" (lucide `Ban`, rose) · `⋯` overflow.
- Groups with more than the shown rows render a "+ {n} weitere Rechnungen anzeigen" footer;
  empty groups render "Keine Rechnungen in diesem Status."

## Interactions & Behavior
- **Collapse** the Überblick (chevron rotates 0↔180°).
- **Segmented toggle** Nach Leistung / Nach Mitarbeiter.
- **Sort** employee table by Umsatz or Marge (click header, toggle direction).
- **Expand** an employee row (Überblick) → per-service breakdown.
- **Pipeline stage click** → tab switch + filter/group-open (see §3).
- **Status chips** (Termine tab) filter appointments; share state with the pipeline.
- **Appointment row click** → navigate to appointment detail (deep link).
- **Tab switch** Termine / Rechnungen.
- **Selection**: global select-all, per-group select-all (stopPropagation), per-row checkbox.
  Selection drives the bulk bar (mass status change + Sammeldruck).
- **Collapsible bill groups** + "Noch zu erstellen".
- Transitions are light (≈120–220ms) on transform/background only.

## State Management
- `collapsed` (Überblick open/closed).
- `view`: `'leistung' | 'mitarbeiter'`.
- `expandedEmp`: employee name | null (Überblick drill-down).
- `sortKey`: `'marge' | 'umsatz'`, `sortDesc`: boolean.
- `month` (and ideally `jahr`, `mitarbeiter`, `kasse`) filter scope.
- `statusFilter`: `'alle' | offen | doku | nachweis | erstellt | versendet | bezahlt` (shared by
  pipeline + Termine chips).
- `expandedAppt`: employee name | null (Termine tab).
- `tab`: `'termine' | 'rechnungen'`.
- `selected`: `Record<billId, boolean>`.
- `erstellenOpen`: boolean; `openGroups`: `Record<groupKey, boolean>`.
- **Data**: replace the prototype's generated arrays with TanStack Query reads. Endpoints implied:
  scoped economics summary (per service + per employee), appointment list (per employee, with
  status + client + service + datetime), bill list (with status, payer, amount, mwst, dates),
  and the "noch zu erstellen" worklist (signed Leistungsnachweise without an invoice, with a
  partial-documentation flag).

## Business Rules (must be exact)
**Rates (€):**

| Leistung | Umsatz | Lohnkosten | Marge | Unit |
|---|---|---|---|---|
| Hauswirtschaft | 38.00 | 16.00 | 22.00 | per Std |
| Alltagsbegleitung | 42.00 | 18.00 | 24.00 | per Std |
| Kilometer | 0.35 | 0.30 | 0.05 | per km |

- **Umsatz** = Σ units × revenue-rate. **Lohnkosten** = Σ units × cost-rate.
- **Deckungsbeitrag (Marge €)** = Umsatz − Lohnkosten. **Marge %** = Marge / Umsatz.
- Compute totals, per-service, and per-employee from the same source so the Überblick is
  internally consistent. (Kilometer is intentionally a thin-margin line ≈14% — surfaced by the
  margin-health coloring.)
- **Appointment lifecycle**: Offen → Dokumentiert → Leistungsnachweis (unterschrieben) →
  Rechnung erstellt → Versendet → Avis erhalten → Bezahlt. Side states: Storniert, Kunde nicht
  angetroffen.
- **Bill lifecycle**: Entwurf → Versendet → (Avis erhalten) → Bezahlt; or Storniert.
