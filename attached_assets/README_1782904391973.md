# Handoff: Mitarbeiterabrechnung & Stundenkonto — Care Connect / Senioren Engel

## Overview
A single, unified surface for the **employee payroll / hours process** in the Care Connect
elderly-care operations app. It merges two previously separate tabs — **Zeiterfassung**
(per-employee time entries) and **Stundenübersicht** (monthly hours per employee) — into one
month-close screen that gives the operator (Geschäftsleitung):

1. A **statistics board** (6 KPIs) incl. a productivity/overhead ratio ("Wasserkopf") and a
   month-over-month growth comparison.
2. An **aggregated table** — one row per employee, hours grouped by payroll category (Lohnart),
   ready to transfer to **Lexware Lohn + Gehalt**.
3. A per-employee **drill-down** with three sub-tabs: **Termine & Zeiten** (the appointment /
   time-block detail), **Aufschlüsselung** (how each aggregated bucket is composed, incl. the
   day→hour conversion), and **Stundenkonto** (a working-time account with editable opening
   balance and paid hours, computing running plus/minus balances).

All UI text is **German — keep it.**

## About the Design Files
The files in this bundle are a **design reference created in HTML** — a working prototype of the
intended look, layout and interactions. **It is not production code to copy.** The task is to
**recreate this design inside the Care Connect codebase** using its established stack and patterns
(the same environment used for the existing **Abrechnung** tab — React + TypeScript, Tailwind v4
`@theme`, shadcn/ui new-york, lucide-react, wouter, TanStack Query). If you also have the earlier
`design_handoff_abrechnung_rework` bundle, reuse the exact same tokens, primitives and status
palette documented there — this screen is a sibling and must feel identical.

`Mitarbeiterabrechnung.dc.html` is a **Design Component** prototype. It renders via the bundled
`support.js` runtime (a lightweight template + logic-class harness) purely so the prototype runs in
a browser. **Do not ship the DC runtime.** Read the file for exact values, formatting (`de-DE`,
`1.234,56`), and the derivation logic in the `class Component` block; re-implement that logic with
real data from TanStack Query.

## Fidelity
**High-fidelity.** Colors, typography, spacing, copy and interactions are final and intentional.
Resolve every inline literal to the corresponding design-system token (see *Design Tokens*).

## Business Rules (must be exact)

### Aggregated buckets → Lexware Lohnarten
Per employee, per month, raw inputs (all in Std unless noted): `hw` (Hauswirtschaft), `ab`
(Alltagsbegleitung), `erst` (Erstberatung), `anf` (Anfahrt/Fahrzeit), `sonst` (Sonstige),
`feier` (Feiertage), `km` (Kilometer), `urlT` (Urlaub in Tagen), `krankT` (Krankheit in Tagen),
`soll` (contractual hours per working day).

- **HW-Sammelposten — Lohnart 100** = `hw + sonst + erst + anf + urlT*soll + krankT*soll`
- **Alltagsbegleitung — Lohnart 110** = `ab`
- **Feiertage — Lohnart 120** = `feier`
- **Kilometer — Lohnart 500** = `km`

### Day → hours conversion
Urlaub and Krankheit are entered in **days** and converted to hours using **the employee's own
contractual daily hours** `soll` (Soll/Tag): `hours = days × soll`. Best practice (Entgeltfortzahlung):
sickness/holiday must be credited as if the person had worked their normal day — never produce
minus hours. Show the conversion transparently (e.g. "3 T → 24,00").

### Stundenkonto (working-time account) — per bucket
For each bucket k ∈ {HW, AB, Feiertage, Kilometer}, kept **separate** (HW and AB are priced
differently, so their balances must not be pooled):
```
Saldo(k) = Anfangsbestand(k) + Erfasst(k) − Bezahlt(k)
```
- **Anfangsbestand** = opening balance, entered **once** when the app goes live in running
  operation (editable). In steady state it becomes the previous month's carried Saldo.
- **Erfasst** = this month's aggregated value (from the buckets above).
- **Bezahlt** = hours/km actually paid out this month (editable, entered by the operator monthly).
- The account **accumulates** month over month — always a live "actual" view.
- Net headline Saldo (hours) = Saldo(HW) + Saldo(AB) + Saldo(Feiertage). Kilometer is tracked in km.
- Sign coloring (Ampel): >0 green (Guthaben/Plusstunden), <0 rose (Minusstunden), ≈0 gray.

### Productivity ("Wasserkopf")
- **Billable / produktiv** = Σ over employees of `hw + ab` (only actual Hauswirtschaft &
  Alltagsbegleitung are billed to clients/Pflegekasse).
- **Non-billable / Gemeinkosten (overhead)** = Σ of `sonst + erst + anf + feier + urlT*soll + krankT*soll`.
- **Produktivquote** = billable / (billable + non-billable).
- **Vormonatsvergleich** = month-over-month growth of billable vs. overhead hours (compute from the
  previous period's aggregates; prototype currently hardcodes +6,4 % / −2,1 %).

### Pay rates (not surfaced in this UI, kept for reference / export)
HW 16,00 €/Std · AB 18,00 €/Std · Feiertage 16,00 €/Std · KM 0,30 €/km. The operator explicitly
asked to **hide all € in this overview** (they read the € as net and found it misleading) — the
table, pills and CSV are **hours-only**. Keep rates available in data for future € reporting, but
do not render € on this screen unless asked.

### Kilometer split (Aufschlüsselung only)
The Kilometer detail row shows two components — **Anfahrt** and **mit/für Kunden**. The prototype
derives them (≈40 % Anfahrt / 60 % Kunden) because the sample data has only a `km` total. In
production, track these as two real fields and sum them for Lohnart 500.

### Unsigned appointments
Documented-but-unsigned appointments are flagged (amber dot + "{n} Termine ohne Unterschrift") and,
in the current prototype, **still included** in the aggregated totals. The operator has questioned
whether they should count; confirm the rule before shipping (either exclude them from Erfasst until
signed, or keep counting and drop the flag's implication).

### Lexware export
The "Nach Lexware exportieren" button builds a semicolon-separated CSV (UTF-8 BOM), one row per
employee per Lohnart with columns `Mitarbeiter; Lohnart; Bezeichnung; Stunden_bzw_KM`. Lexware
Lohn + Gehalt imports abrechnungsrelevante Stunden per Lohnart via its ASCII/CSV import assistant.

## State Management
- `month` — period scope (drives labels + Vormonat comparison).
- `expanded` — employee name | null (which drill-down is open; single-open).
- `subtab` — `Record<employeeName, 'termine' | 'auf' | 'konto'>` (default `'auf'`).
- `openRaw` / `paidRaw` — `Record<employeeName, Record<bucket, string>>`: operator edits of the
  Anfangsbestand and Bezahlt inputs (parsed `de-DE`, comma decimal). Persist per employee/month.
- **Data**: replace the prototype's generated arrays with TanStack Query reads. Endpoints implied:
  per-employee monthly aggregate (the raw fields above + `soll`, `type`, `unsigned`), the appointment
  list per employee (client, datetime, service, status), the previous-month aggregate (for growth),
  and the stored account balances (opening + paid history).
